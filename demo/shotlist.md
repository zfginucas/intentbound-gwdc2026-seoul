## Edit rules

- The current [52-second preview](intentbound-preview-no-payment.mp4) covers only the workbench, live Kiln calls, review screen, and usage. Do not splice it into a “paid” story without a new verified capture.
- A and B are successful safety outcomes. Give the red rejection states more screen time than the model chat. C gets one actual transaction hash, never a typed placeholder.
- Use the captured `raw-ui.webm` for cursor movement and button presses, and the validated `shots/*.png` for legible holds. Keep narration synchronized with the exact product state; the silent animatic is an edit guide rather than the final cinematic cut.
- If a live network call stalls, show a modest “Waiting for Kiln/Shasta” state or switch explicitly to a prerecorded verified run. Never hide a failed call behind scripted fallback while narrating it as live.
- The final on-screen disclosure should read, in substance, “Simulated merchants and delivery; real Kiln calls and TRON Shasta testnet decisions.” Keep the demo owner wallet custody note visible in the authorization segment.
