# Intent Constitution - 早期概念草案

> 本文件保留早期思路，不作为当前开发或汇报的完成状态依据。Personal AI 点外卖的现行方案见 [01_IntentBound_详细设计方案.md](./01_IntentBound_详细设计方案.md)。下文关于 ZK、LTL、节能比例、已完成项及 15 分钟 PPT / 5 分钟视频的描述均未获实现证据或已与赛事要求不符。

## 一句话描述
A policy-enforced wallet system that transforms fuzzy natural language authorization into formal "spending constitution", validates every transaction with constitutional citations, and maintains an immutable audit trail using zero-knowledge proofs.

## 核心问题

### Challenge B 要解决的问题
> "AI Agent 花钱后，如何证明它在授权范围内？如何在争议时拿出证据？"

### 传统方案的缺陷
```
用户："帮我订晚餐，别太贵"
传统系统：
  budget = 50  # AI 猜的
  whitelist = ["餐厅"]  # AI 猜的
  
问题：
  ❌ 猜测用户意图，可能理解错
  ❌ 事后无法证明"当时用户同意了这个理解"
  ❌ 争议时各说各话
```

### 我们的创新
**把模糊的自然语言授权 → 形式化的"消费宪法" → 每笔交易必须引用条款 → 链上可验证**

```
用户："帮我订晚餐，别太贵"
我们的系统：
  1. AI 理解意图 → 生成宪法草案
  2. 用户确认/修改 → 签名
  3. 宪法上链（不可篡改）
  4. AI 每次花钱必须引用条款
  5. 事后争议 → 打开宪法，逐条核对
  
优势：
  ✅ AI 的理解是显式的、可确认的
  ✅ 用户授权是形式化的、可验证的
  ✅ 争议解决是客观的、有依据的
```

## 六大技术创新

| 技术 | 作用 | 创新点 |
|------|------|--------|
| **Constitutional AI** | 意图形式化 | Anthropic 的 Constitutional AI 首次应用在财务授权场景 |
| **Neuro-Symbolic Reasoning** | 混合推理 | 神经网络理解语义 + 符号系统验证逻辑 |
| **Temporal Logic (LTL)** | 时序约束 | 验证跨交易的时间序列约束（如每周预算） |
| **Zero-Knowledge Proofs** | 隐私保护 | 证明合规但不暴露敏感信息（企业场景） |
| **Adversarial Agent** | 安全测试 | 红队 Agent 实战攻击，验证系统鲁棒性 |
| **FuriosaAI NPU** | 高效推理 | 所有 LLM 推理用 NPU，能效提升 75% |

## 差异化优势

### vs 传统规则引擎
| 维度 | 传统方案 | Intent Constitution |
|------|---------|-------------------|
| 意图表达 | 人类写死规则 | AI 理解后生成宪法 |
| 用户参与 | 无（黑盒） | 必须确认宪法 |
| 可解释性 | 低（if-else） | 高（条款引用） |
| 争议解决 | 困难 | 客观（链上证据） |

### vs 简单审计系统
| 维度 | 简单审计 | Intent Constitution |
|------|---------|-------------------|
| 验证粒度 | 事后查看日志 | 事前形式化+事中验证+事后审计 |
| 时序约束 | 不支持 | 支持（Temporal Logic） |
| 隐私保护 | 无 | ZK Proofs |
| 安全测试 | 无 | 对抗性 Agent |

### vs 其他参赛作品（预测）
- 大部分会做：硬编码规则 + 简单日志
- 我们的优势：
  - ✅ 学术深度（6 种前沿技术）
  - ✅ 工程完整性（端到端可运行）
  - ✅ 叙事能力（"消费宪法"概念性感）
  - ✅ 实用价值（解决真实痛点）
