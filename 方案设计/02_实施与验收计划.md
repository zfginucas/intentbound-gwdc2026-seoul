# IntentBound - 实施与验收计划

> 本文件是执行清单，未勾选项不代表完成。所有展示给评委的 Kiln 用量、链上哈希和付款结果均须来自真实运行。模拟餐厅与配送数据必须在界面、视频和 PPT 中标明。

## 目标与实施顺序

先让一条真实的 TRON 测试网付款闭环跑通，再补齐两种拒付、撤销、独立审计、丰富前端和演示材料。前端可先用固定模拟菜单完成交互，但不能给尚未连通的链上操作显示“成功”。

1. 工程与安全：仓库、忽略密钥、运行脚本、环境变量示例。
2. TRON：受限会话合约、编译/部署、测试网账户与测试币、真实交易与事件。
3. Kiln：qwen3-32b 实际调用意图解析和菜单推荐，记录每个流程的 token、耗时和生成 ID。
4. 策略与证据：含费合计、地址白名单、到期、累计预算、撤销；四个可重放场景；证据包与独立审计。
5. 前端：直接进入 Dinner Run 工作台，完善授权、观察、拒付详情、停止、收据与公开审计。
6. 质量与交付：测试、桌面/手机截图检查、真实使用数据表、短视频、Pitch Deck、提交材料。

## 演示与声明边界

可模拟：餐厅、菜单、食物图片、配送员、ETA、订单号与配送状态。

不可编造为真实：Kiln 请求与 usage、模型型号、链上交易/事件/余额、授权签名、测试结论和能源实测。若只能把记录写到链上而非合约阻止付款，必须称“链上留证 + 应用层拦截”，不能称“链上强制消费控制”。
